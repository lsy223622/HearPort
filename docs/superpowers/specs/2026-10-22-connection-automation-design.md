# 日常连接与自动化

## 目标

已配对设备在可恢复连接时自动连接；用户主动断开、身份拒绝和取消配对停止重试。Windows 保持登录后托盘启动，移动便携目录后能修复已经启用的启动项。iPad 提供可在一次实机验证中比较的快捷指令入口。

## 约束

- 复用现有 QUIC、配对和音频控制链路，后台动作不依赖页面出现。
- iOS 16 / Swift 5.9；发布产物由 GitHub Actions 生成。
- 网络或进程波动不删除凭据。只有已有的明确取消配对流程允许删除。
- 不用静音保活；未连接时不能承诺 iOS 持续运行。普通动作、音频动作、前台动作分别记录结果。
- USB 专用动作不回退网络；网络专用动作不被 USB 抢占。自动路线仍优先 USB。
- 重复动作幂等；测试运行时不被自动化打断。URL 不接收地址、PIN、凭据或任意回调。

## 设计

将现有页面状态和连接方法迁入进程级 ReceiverRuntime，SwiftUI 观察同一个实例。启动、回到前台和网络恢复按连接意图恢复；手动断开暂停本次进程内自动恢复，明确连接动作重新启用。已验证服务器正常停止视为暂不可用，诊断测试正常完成保留现有完成界面。

快捷动作包括播放（AudioPlaybackIntent）、后台连接、打开并连接、断开、读取状态和记录触发标记。连接动作支持自动/仅网络/仅 USB。URL 入口提供对应前台连接、断开和状态页。每次动作记录请求 ID、进程 ID、冷启动、系统版本、执行环境、连接/认证/引擎阶段及耗时；动作返回不冒充已经收到音频。

App Shortcuts 提供直接可用动作；测试包生成无个人数据的 URL 快捷指令及原生动作配置表，在 macOS CI 尝试签名并保留真实结果。Wi-Fi/充电器个人自动化由用户在设备上授权，充电触发不等于电脑 USB 数据已就绪。

## 验收

纯策略、路线限制、URL 拒绝规则、重复动作和 Windows 启动命令解析有回归测试。CI 验证 iPad AppIntents 元数据和应用构建。实机表区分触发、进程启动、连接和实际出声，覆盖锁屏/后台/首次启动/电脑恢复/重复触发；未执行项不标成功。
