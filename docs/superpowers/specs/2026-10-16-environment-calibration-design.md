# HearPort 当前环境校准与参数推荐

日期：2026-10-16。状态：待用户审核；尚未实现。

## 1. 目标

用户在实际使用的位置运行一次随机数据测试，获得当前链路的延迟—稳定性曲线，以及低延迟、平衡、稳定优先三档参数。结果取决于本次环境、负载、设备和输出方式，不作为其他网络或未来时段的保证。

本版复用网络测试、时钟映射、播放控制器和诊断回传。保持现有实际播放控制算法，校准选择它的配置。不增加额外缓冲层，不开发音频缺口预测算法，不要求用户改变网络路径。

## 2. 流程与首版范围

Windows 诊断页的网络测试设置增加“环境校准”用途；已有传输对比测试仍可选择。设置包含允许的最大总延迟，以及每组时长（默认30秒，可选60/120秒）。上限默认采用用户当前设置，仍受现有协议的2000毫秒限制。开始后自动转概览，显示采样、分析、复核、回传阶段。

iPad 连接一次，自动完成两种传输模式的测试，不播放音频。采用与生产相同的48kHz、双声道float32、每包120帧、每秒400包、992字节TimedAudioRecord、单包匀速发送。首版仅推荐生产已经支持的配置；不把降低数据率的实验变体当作相同音质的优化。

一次校准包含：

1. **采样**：Datagram/Reliable各两组，按随机选择的ABBA或BAAB顺序运行，共四组。组间沿用5秒恢复间隔，每组独立代际和记录边界。
2. **分析**：结束采样后在iPad后台串行评估接收端候选，显示进度；此阶段不发送额外数据测试流量。曲线必须在同一组输入上比较候选，不能用前一组测80ms、后一组测160ms。
3. **复核**：对选出的三档配置，按新的随机顺序运行一轮，再反序重复。每组使用该配置真实的发送期限、Reliable换代、接收控制和反馈。重复配置合并测试；不合格档位不强行生成复核任务。
4. **回传与结果**：保留现有报告落盘、确认回收流程；两端显示曲线、推荐、复核状态和观测限制。

最多十组，默认数据传输300秒、九个5秒间隔和10秒收尾，另加分析、握手和报告传输时间。界面展示根据实际任务数计算的预计时长，不写死总秒数。

## 3. 两类证据必须区分

### 3.1 相同输入的接收端比较

采样使用用户允许的最大预算作为采集期限，避免以较小期限提前丢弃所有较大候选仍可能使用的数据。记录首次接收、原始采集时间、映射时间、不确定度、源帧、序号、代际、组别，以及接收调度时间。

即使如此，Reliable排队、主动换代和发送端丢弃仍受采集配置影响。因此回放结果只说明“这份已观测输入下的接收效果”，不能假定更换期限后发送端会产生同样轨迹。没有到达的数据统一记为本次未接收，不推定为物理网络永久丢失。

候选共用相同到达事件、首次到达去重规则、时钟边界、起止范围和消费时钟。评估在采样完成后进行，不能根据整份轨迹的未来信息提前改变当时的控制决策。

### 3.2 推荐参数的真实复核

复核阶段让服务器和iPad实际采用推荐期限和反馈策略。它检验回放推荐能否用于当前真实链路，但其新网络输入与采样不同，不能把差值单独归因于设置改善。

报告分别保留采样回放、两次复核和按时间分组的波动。复核变差、两次相互矛盾或条件改变时，推荐标记为暂定/未达目标，不显示已保证稳定。

## 4. 接收端评估

复用`ProbeConsumer`及其`PlayoutController`，在独立实例内按记录的事件时间顺序回放；每个实例有自己的缓冲和控制状态。被动实例不发送任何播放反馈、重传请求，也不改变服务器队列。实际采样/复核始终只有一个实例拥有反馈权。

回放只保存和消费必要的包元数据，不为各候选复制随机负载，不生成音频，也不调用音频输出；串行处理候选，避免采样期间的额外计算干扰网络结果。

校准流不播放音频，故这些指标是源音频可用性与播放控制参考，不宣称已经测得完整音频DSP、render ring或声学端到端效果。另提供与控制器无关的固定截止时间覆盖曲线，用于解释网络尾延迟。

候选最大延迟取`40/60/80/100/120/160/200/300/500/750/1000/1500/2000ms`中不超过用户上限的值，并加入用户上限本身。每个最大值评估正常目标为其50%、75%、以及最大值减5ms的组合；正常目标向上取整至5ms，必须大于输出预留，并去重。无法容纳输出和控制余量的组合不参与推荐。

输出预留通过现有音频会话能力获取；若仅能估计，结果明确记录估计值。时钟不确定度在所有候选中一致扣减。输出预留、处理预留、接收缓冲均占用同一份总预算。

指标包含：

- 及时收到的原始源时长占比，以及固定截止时间下的连续不可用区间。
- 控制器回放中的原音播放、补偿、等待、源跳过和实际消费源时长。
- 启动等待单独统计，运行中缺口包含等待及跳过造成的中断；不同类型不重复累计。
- 连续运行中缺口的数量、分布和最长值，不能把原音之间的空洞平均掉。
- 正常目标、实际源年龄P50/P95/观测最大值、使用的最大预算，以及变速幅度和持续时间。

源年龄包含统一输出预留；缺失/跳过源内容不以变速后的输出帧数代替。尾部不足以观察完整消费的区间截断并标记，不假定未收到的最后一个包一定已经丢失。

## 5. 三档选择规则

三档都在用户上限内选择；不按传输模式名称预先决定优劣。先去除在观测源年龄、不可用源时长和最长缺口上均不占优的候选，再应用以下可见规则。

| 档位 | 首版观测目标与排序 |
|---|---|
| 低延迟 | 运行中不可用源时长占比不超过0.5%，最长缺口不超过40ms；达标候选中优先较低源年龄P95，再优先较少缺口 |
| 平衡 | 运行中不可用源时长占比不超过0.1%，最长缺口不超过20ms；达标候选中优先较低源年龄P95，再优先较少缺口 |
| 稳定优先 | 在用户上限内优先最少不可用源时长，其次最短最长缺口，再选较低源年龄；相同观测效果选更低预算 |

上述百分比和缺口长度是首版产品选择策略，不是已验证的听感分界，也不是未来中断概率保证；在结果页可查看。采样不能满足某档目标时显示“当前上限内未达该档目标”，保留最佳观测点供查看，不伪装成达标推荐。三个档位可以得到相同设置。

选择只使用采样阶段；复核数据不反复参与调参。复核达不到原目标则降低状态并展示实际数值。高稳定性也必须显示尚有多少缺口，不能用其名称暗示不会中断。

## 6. 网络波动与可信程度

同一组轨迹的候选逐时间段配对；报告每个30秒采样组及其中5秒连续块的差异。可对连续块作固定种子的配对重采样，展示比较的波动范围，不能把每个包当作独立试验。跨模式比较保留独立输入和重复结果，不标记为相同网络遭遇。

两次采样和两次复核仍不足以证明稀有故障率。零缺口仅表示本次未观察到；重复结果重叠不能证明两个配置等效。时钟缺失、记录溢出、测试未完成、切后台或输出条件变化时显示具体限制；不足以形成可用建议时仅提供已记录结果。

## 7. 两端职责与协议

- Windows `network_probe`负责校准轮次、精确发送、按轮配置真实预算；`sender_service`复用现有探测工作线程和状态回收。GUI负责设置、阶段进度和结果展示。
- iPad新增校准计划/结果模型，复用`DebugSessionDiagnostics`的元数据采集、`ProbeConsumer`和报告传输；分析在采样后独立队列执行，可取消，不持有接收锁进行长计算。
- 使用新的校准能力协商位，双方明确支持后才开始。校准计划/下一阶段指令通过现有`probeManifest`的独立版本编码；不改变现有网络测试和音乐测试编码的含义。
- 新计划包含阶段、每组时长、每组传输/正常目标/最大预算、源与序号边界。每轮在双方确认配置后开始，超时按失败结束，不能静默跑成另一种测试。
- iPad返回采样推荐；Windows只对本会话采样中的候选接受复核计划，仍校验用户上限和参数范围。报告包含版本、会话、配置、输入指纹、数据完整性、曲线及复核结果。
- 校准后在iPad保存本次三档结果，供用户点击应用到现有传输模式、正常目标和最大延迟设置，下次连接生效；不在播放中强制切换。Windows展示同一报告。设置中传输名称使用Datagram/Reliable，避免与三档场景名称混淆。

## 8. 运行时与隐私

继续使用已有单一自适应播放控制器，在选中预算内运行；本版不新增另一套在线调参器，也不自动覆盖用户偏好。结果保存测试时间、设备/输出条件和配置。用户换位置或网络后可重新校准；不扫描或持久化SSID，不把位置名称当作可靠网络身份。

随机负载、报告、原始记录和结果保留在现有本地诊断位置。无需真实音乐、文件路径或偏好信息。重连/后台/中断时保留已获得的诊断，但不把半次测试发布为完成的推荐。

## 9. 验证与交付

1. 相同轨迹/时钟下候选输入一致；固定期限加宽不会凭空补出未接收数据。
2. 回放因果性、输出预留、不确定度、源覆盖记账、尾部截断和长连续缺口有针对性用例。
3. 主动实例独占反馈；推荐预算影响发送期限与Reliable换代，并在复核中实际生效。
4. 三档选择、无达标点、相同推荐合并、重复不一致、数据不全和用户上限有确定性用例。
5. 两端计划编码一致，旧端拒绝校准时提示更新，现有诊断回收不受影响。
6. 本地运行相关Windows单元测试与GUI构建；iPad测试与安装包通过GitHub Actions。端到端实际环境验证由安装更新后的设备完成，不把离线回放当作已完成实机校准。

实现前先审核本稿中的范围、三档策略阈值与两阶段证据边界，再编写逐项实现计划。避免把本次首版扩展为新的音频格式、编码器、修复机制或额外传输路径研究。
