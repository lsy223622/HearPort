# USB listener recovery and long-session diagnostics

## Evidence and scope

The physical-device failure was present on iPad build 170 while LAN audio still
worked. Windows continued to discover the USB device and received usbmux Connect
result 3 (connection refused) for port 52138. The iPad export had already rotated
past listener startup events, so it does not establish the original OS transition
or prove an idle expiry. Raw evidence remains local.

Two reproducible application recovery gaps were isolated:

- Starting again retained a non-nil listener object even when it no longer
  accepted connections. App foreground entry did not refresh the idle listener.
- A failed USB attempt entered cooldown; successful LAN fallback could cancel the
  retry timer, leaving no event to retry USB after cooldown expired.

Regression Actions 39416555707 reproduced both on the old behavior: 196 tests ran,
only the two new cases failed (timeout and corresponding state assertions).

## Changes

Refresh idle TCP listeners on foreground entry, retaining accepted USB connections.
Bound recovery from waiting/cancelled/failed listener states, ignore stale listener
callbacks, and keep listener failures separate from established forwarding.
Retry a matching available USB route after cooldown even while LAN remains active;
diagnostic route pinning and authenticated identity checks remain in force.

Raise both runtime log budgets to 16 MiB per file plus seven backups (128 MiB per
endpoint). Keep the in-memory tail bounded. Snapshot open log handles and lengths
under the writer lock, then stream 64 KiB chunks outside that lock on a background
queue. Export captures current USB listener/TCP/forwarder state and shows progress.
Windows repeats unchanged USB status at most once per 30 seconds to show continued
retry activity without flooding logs.

## Verification

Local Windows Release build and 24 CTest checks passed, including retention of a
startup marker beyond the former default history. Swift regression, established
tunnel preservation, Unicode export and expanded retention run in Actions.
Both release programs must be generated by Actions. Physical repeat acceptance
remains separate from the simulated listener/coordination regressions.
