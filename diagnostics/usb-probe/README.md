# USB feasibility probe

This is a disposable transport probe, separate from the HearPort application.
It sends generated bytes over Apple's USB multiplexer to a loopback listener in
an ordinary iPad app. It does not carry personal audio or pairing credentials.

## Run

1. Install the `HearPortUSBProbe-unsigned.ipa` produced by the manual
   **USB feasibility probe** GitHub Actions workflow using the existing signing
   and sideloading method. It installs alongside HearPort.
2. Connect the iPad with a data-capable USB cable, unlock it and trust the PC if
   prompted. Windows needs the Apple Mobile Device service.
3. Open **HearPort USB Probe** on iPad and tap **开始监听**.
4. On Windows, run `Run-USB-Probe.cmd` (Python 3.11 or later). It waits up to ten
   minutes for the app, then runs a three-minute session. Logs go to ignored
   `out/usb-probe/`. Only one USB Apple device should be attached.

For a different duration:

```powershell
python diagnostics/usb-probe/usb_probe.py --seconds 300 --wait 120
```

The stream has 400 generated 960-byte payloads per second, each with a 32-byte
header, sequence and CRC32. Ten small ping/pong exchanges per second measure
host-observed round-trip time, subtracting the iPad's reported reply processing
time; this is not one-way or acoustic latency. The sender records pacing and
blocking so PC scheduling is not attributed to USB.

A result is complete only after final receiver counts return. Disconnects and
three-second reply stalls are recorded, then the host waits for reconnection
and restarts the session. Manual Ctrl+C stops the host. iPad lifecycle events
can be exported with **导出 iPad 探针日志**. Keeping the screen on is enabled by
default; manual lock/unlock can be tested separately. Because this probe has no
playback session, suspension after locking does not establish how the eventual
background audio mode will behave.

The listener binds only to `127.0.0.1:52138`; the host filters out devices found
through network discovery. This prototype stream has no application TLS or
HearPort authentication and is restricted to generated test data. Production
security and playback integration are a separate step after device feasibility
is established.
